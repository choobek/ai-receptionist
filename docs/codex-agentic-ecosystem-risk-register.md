# Codex Agentic Ecosystem Risk Register

| ID | Risk | Current evidence | Impact | Mitigation | Detection / containment |
| --- | --- | --- | --- | --- | --- |
| R1 | Duplicate n8n workflows create drift between repo intent and runtime reality | Staging and production both contain legacy workflow copies beside `aiReceptionist*` IDs | High | Keep `reconcile-n8n-workflows-vps.sh` mandatory and expose duplicate detection in `n8n-read` | Always capture `n8n list:workflow` and `n8n list:workflow --active=true` in runtime audit packets |
| R2 | Dashboard-only or UI-only edits bypass Git authority | Repo rules explicitly forbid this for both Vapi and n8n | High | Make all write MCPs wrap current repo scripts only | Add rendered-vs-runtime drift reports and block write flows when repo and runtime disagree |
| R3 | False drift reports from comparing shared config to runtime instead of rendered env config | Staging intentionally overrides shared Vapi transcriber and speaking settings | Medium | Always compare runtime to `render-vapi-assistant-config.sh <env>` output | Make `runtime-drift-audit` render first and report the binding file used |
| R4 | One agent diagnoses, patches, deploys, and grades its own change | Phase 3 role definitions and the boundary checker now exist, but the separation must remain enforced as the control plane evolves | High | Split patch, sync, and evaluation into different subagents | Reject agent definitions that combine patch and staging-write authority |
| R5 | Production mutation becomes casual or silent | Current repo model is explicit, clean-tree, exact-ref based | High | Keep production disabled by default and route all promotion through `promote-to-production.sh` | `ops_guard` must refuse production unless explicitly enabled and asked |
| R6 | n8n credential state is mistaken for versioned repo state | Credentials are not stored in Git and reconcile copies them from donor workflows | High | Keep credential handling inside current reconcile flow only | Runtime audits must record missing-credential findings and stop writes |
| R7 | Embedded workflow data drifts from source JSON | Service catalog and KB data are embedded into workflow JS | Medium | Keep `sync-n8n-workflow-data.sh --check` in every release gate | Block workflow staging sync if the check fails |
| R8 | One-off call failures push prompt growth instead of invariant-based fixes | Testing docs already warn against broadening shared behavior from narrow cases | Medium | Keep release gates focused on durable contract/chat checks and use call-triage for live-call evidence | Require repeated real-call evidence before adding shared prompt rules |
| R9 | Saved Vapi eval lane is treated as a release gate | Repo docs explicitly say the lane can still time out | Medium | Keep it diagnostic-only in skills and MCP output | Release gate wrapper should label it advisory, not blocking |
| R10 | Secrets or real-call PII leak through MCP responses or generated reports | Root `.env` contains live credentials and live autoeval handles real calls | High | Redact secrets by default, keep real-call artifacts under git-ignored paths | Add a report redaction pass and refuse to commit generated real-call artifacts |
| R11 | Local-only edits are mistaken for deployed staging state | The current autonomy loop already warns that local workflow edits are not staged until VPS sync happens | High | Make `ops_guard` record git SHA, changed files, deploy step, and sync step separately | Every staging sync packet should show pre-sync SHA, deployed SHA, and post-sync runtime audit |
| R12 | Baseline verification quietly rots | Repo-health surfaced stale archive links during this audit | Medium | Keep repo-health in the first verification slot and fix failures immediately | Treat a red repo-health result as a stop condition, not a warning |
